## 0:00–1:30 · 架构 + 两个必答题

【屏幕】`docs/architecture.png` 全屏

> CNC 加工厂收到的询价，是邮件加 Excel、PPT、PDF，有时是扫描件。现在是估价员读文件、查价格、算数、回信。
> 我做了一个 agent 来干这些活，但它自己从不产生任何数字。

> 五层。邮件进 S3；Runtime 跑 agent.py；Gateway 暴露十四个工具；活是工具干的；交付物写回 S3。
> 工具里面是八步：接入、解析、抽取、语义理解、归一化、定价、复核、交付。
> 模型只读文字——价格、折扣、审批，全部是代码。

> 必答题一：我用三样。Runtime 管托管，Gateway 管工具和鉴权，Memory 管状态。
> 另外四样不用：Identity、Code Interpreter、Browser、深度可观测。只有一个调用方——而且价格必须留在我的代码里。

> 必答题二：从我在生产用的 LangGraph 栈里，我留下三样：流程可见、每一步可测、必须有人点头。
> 我换掉三样：托管、我自建的 MCP server、Mongo checkpointer，改成 Runtime、Gateway、Memory。
> 而且这里不用框架——这条链路是直的，八个普通函数比一张图更好讲。

## 5:00–7:00 · 问题：决定了什么 / 问了人什么 / 假设了什么

【屏幕】回到工作台的报价结果

> 顺利的部分讲完了。现在讲问题，我按三段说：它自己决定了什么、它问了人什么、我假设了什么。

> 第一段，它自己决定的。数量取最权威的那份文件：图纸优先，其次表格，最后邮件正文。
> 折扣来自数量档位：五百件 5%，一千件 8%。某一行的价算不出来就挂起，绝不猜。
> 总额或折扣越过政策线，它自己就走进审批流程。

【屏幕】依次指 SPC-050、HSG-400、CVR-310，再切 `/approvals`

> 第二段，它问了人什么。垫片：数量还在等客户确认，工装费没法分摊——挂起，回信里向客户要这个数。
> 阀体：钛合金五级不在价表上，公差又比任何标准费率都紧——一行上两个缺口，转给采购和工程。
> CVR-310：图纸写八百，表格写一千——按权重取数，同时把冲突标出来等人确认。
> 还有 15% 的折扣：超过我们 8% 的上限，交给销售经理决定。

【屏幕】停在报价页，或切到 README 的已知限制

> 第三段，我假设了什么。有效期三十天。25% 指的是毛利率，所以售价是成本除以 0.75，而不是成本加 25%。
> 档位按每一行自己的数量算。五万马币是经理签字的线，8% 是折扣上限，缺失的值一律挂起、绝不补。
> 这些都写在 README 里，没有埋在代码里。

## 7:00–8:00 · 成本、追踪、改进

【屏幕】指界面上 `Model calls this quote:` 那一行

> 每份报价的成本。确定性路径不调用任何模型——界面就写着。
> 兜底真的跑起来，是一次调用、一两千个 token，而且表头映射按模板指纹缓存。
> AWS 这边是一次 Lambda、几百毫秒 Runtime、几 KB 的 S3：一份报价几分钱的一小部分，
> 而估价员手工做一次要二十分钟。

【屏幕】CloudWatch 日志，再回 `how?`

> 追踪分两层。平台层：每次 Runtime 调用都有自己的 session id 和 CloudWatch 日志。
> 业务层：每次解析都记录哪个解析器版本产出了哪几行——所以“哪个文件、哪一行、哪条规则”这个问题已经有答案，
> 复核清单还会把这条链重复给签字的人看。

> 三件事我会改进。图表：OCR 能读标签，读不到画在图里的数值，数量只写在柱状图里就读不出来——这需要视觉模型。
> 审批：现在会进队列，但没人收到邮件——需要 SES。
> 还有可信度权重：90/70/60/45 是我的判断，不是学出来的——应该用标注过的报价去拟合。

| 列表空 / 401 | “凭证过期了，我重新登录。” |

## 三句别念错（英文录屏请按英文版说）

1. 不是“模型算价格”，是 **“模型读文字，代码定价”**
2. 不是“审批已自动化”，是 **“队列和状态能用，通知还没做”**
3. 不是“全自动”，是 **“能算的算，算不出的挂起并写明缺什么”**
